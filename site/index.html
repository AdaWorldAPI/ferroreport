Small reports are dominated by JVM start-up and JRXML compilation. Counting only Jasper's fill and export phases, ferroreport is still about 85× faster on small reports and 13× on the large one, and its PDFs are a quarter of the size.

Better than the original where it matters

A drop-in engine for the reports you already have, built to be fast, small and safe.

Pixel-identical

Every test report is rendered by both engines and compared pixel by pixel: text metrics, line breaks, page splits, groups and variables follow Jasper exactly.

Safe with any template

No .jasper deserialization, no Java code in expressions, no network. Images and subreports only load from directories you allow.

One engine, any language

CLI, Rust library, JavaScript and WebAssembly, Python, and an HTTP API in an ~8 MB Docker image for Java, C#, PHP, Go and the rest.

The features you use

Bands that split across pages, frames, images, subreports, charts, QR codes and Code 128, styled and HTML text, rotation, multi-column layouts, conditional styles.

Ready for serverless

It starts in milliseconds instead of seconds, which suits Lambda, Cloud Run, edge functions and command-line tools.

Free and open source

MIT or Apache-2.0, built for the community. Contributions and new test templates are welcome.

Install

Pick the way you want to call it. Every option uses the same engine and produces the same PDF.

The npm, PyPI and crates.io packages are published with release 0.2.0, which is on its way. The binaries and the Docker image work today. Every function and option is described in the documentation.
