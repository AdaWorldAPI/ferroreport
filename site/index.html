JasperReports-compatible · no JVM

The fastest way to render your JasperReports.

ferroreport reads the .jrxml templates you already have and turns them into PDF in milliseconds. The output matches JasperReports pixel for pixel, it needs a tenth of the memory, and templates can't run code on your server.

Small reports are dominated by JVM start-up and JRXML compilation. Counting only Jasper's fill and export phases, ferroreport is still about 85× faster on small reports and 13× on the large one, and its PDFs are a quarter of the size.

Better than the original where it matters

Pixel-identical

Every test report is rendered by both engines and compared pixel by pixel: text metrics, line breaking, page splits, groups and variables follow Jasper exactly.

Safe with any template

No .jasper deserialization, no Java code in expressions, no network. Images and subreports only come from directories you allow.

One binary, any language

CLI, Rust library, JavaScript/WebAssembly, Python, and an HTTP API in an ~8 MB Docker image for Java, C#, PHP, Go and the rest.

Everything you use

Bands split across pages, frames, images, subreports, charts, QR codes and Code 128, styled/HTML text, rotation, multi-column layouts, conditional styles.

Serverless-ready

Starts in milliseconds instead of seconds: ideal for Lambda, Cloud Run, edge functions and CLIs.

Free and open source

MIT or Apache-2.0. Built for the community; contributions and new test templates are welcome.

Playground

Runs entirely in your browser (WebAssembly). Edit the template or the data and render again.
